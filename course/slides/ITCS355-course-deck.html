Why01 Reproduce02 Track03 Serve04 Operate05 Cloud
The gap this course closes

You already know how to fit a model.
That is the small part.

Model code is a thin box inside a much larger system of data plumbing, serving infrastructure, configuration, and monitoring. Most production failures live in the box you didn't write.

What courses teach

Clean dataset, fixed split, one metric, one machine, one run.

What production is

Data that shifts, traffic that spikes, dependencies that rot, costs that compound, users who complain.

What we do here

Build the surrounding system, break it deliberately, and measure what happens.

Pre-reading before Session 1: Sculley et al., Hidden Technical Debt in Machine Learning Systems (NeurIPS 2015). Nine pages. Bring one question.

A term with two meanings — we use both, deliberately

MLOps, and the other "AIOps"

The course

Operating AI systems

MLOps: versioning, tracking, deployment, drift, retraining, cloud platforms. This is Sessions 1, 2, 3 and 5.

One segment

AI for IT operations

Using ML on telemetry itself — anomaly detection over logs and metrics, alert correlation, noise reduction. Session 4 only.

They meet at one point, and it is the interesting one: the system that monitors your model is itself a model, with its own false positives and its own way of being ignored.

Entry01 Reproduce02 Track03 Serve04 Operate05 Cloud
Assumed, taught, and out of scope

Where you start

Assumed

Python fluency. Git basics. One prior machine learning course. Basic Linux shell. Comfort reading API documentation.

Taught here

Docker. Experiment tracking. Model registries. Serving and scaling. CI/CD. Observability and drift. Cloud MLOps platforms. Cost.

Out of scope

Model architecture research. Pre-training. Deep networking. Kubernetes internals. Formal SRE theory.

No prior Docker or cloud experience is required — but Week 0 setup is mandatory and takes about 90 minutes. Arriving at Session 1 without it costs you the first lab, and the labs compound.

Arc01 Reproduce02 Track03 Serve04 Operate05 Cloud
Five topics, one artefact

The through-line

You build a single system across the whole term. Nothing is a toy example discarded at the end of the day, and the capstone is an extension of your labs rather than a separate effort.

# the same repository, five sessions running S1 notebook.ipynb → Dockerfile + train.py + versioned data S2 → tracked experiments + registered model v3 S3 → /predict endpoint, p95 < 200ms, load tested S4 → push → test → deploy, dashboards, drift alert S5 → running on managed cloud MLOps services

The rail at the top of every slide shows which stage you are in.

Course brief01 Reproduce02 Track03 Serve04 OperateFinal week
Final week · no new content

Presentations
and defence

Project presentation

8 minutes plus 5 minutes of questions. The problem in 60 seconds, the architecture, a live demo, the failure you engineered, your costs, and what another week would buy. Expect unexpected input to be sent during your demo.

Quiz 5 and submission

The final quiz is held this week. There is no final examination. Your repository is due 7 days later, and the five rubric criteria are marked from what is in it.

The demo carries 5 of the project's 50 marks. A system that only runs when its author is holding it loses them.
